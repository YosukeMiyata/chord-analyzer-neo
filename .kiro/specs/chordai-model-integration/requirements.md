# 要件定義書

## はじめに

この機能は、現在のテンプレートマッチングによるコード認識システムを、anime-songリポジトリのChordAI事前学習済み機械学習モデル（https://github.com/anime-song/ChordAI）に置き換えます。現在のテンプレートマッチング方式は、マイナーコードとベース音検出の精度が低いです。ChordAIモデルは、参照アプリケーション（https://booth.pm/ja/items/7957208）で使用されているものと同じモデルであり、優れたコード認識品質を実証しています。

## 用語集

- **ChordAI_Model**: anime-song/ChordAIリポジトリの事前学習済み機械学習モデルで、音声特徴からコード認識を実行する
- **Template_Matcher**: クロマ特徴をハードコードされたコードテンプレートと比較する現在のコード認識システム
- **Chord_Estimator**: コード認識を担当するシステムコンポーネント
- **Chroma_Features**: ピッチクラスのエネルギー分布を表す12次元特徴ベクトル
- **Bass_Note**: コードの転回形を定義する最低音
- **Chord_Quality**: コードの種類（メジャー、マイナー、ディミニッシュ、オーグメントなど）
- **Audio_Pipeline**: ファイル入力からコード出力までの完全な音声処理ワークフロー
- **Model_Weights**: ChordAIニューラルネットワークの学習済みパラメータ
- **Inference_Engine**: 入力特徴に対してChordAIモデルを実行し、コード予測を生成するコンポーネント

## 要件

### 要件1: ChordAIモデルの読み込み

**ユーザーストーリー:** 開発者として、ChordAI事前学習済みモデルを読み込みたい。そうすることで、システムがコード認識に使用できるようになる。

#### 受け入れ基準

1. Chord_EstimatorはChordAIリポジトリ形式からModel_Weightsを読み込むものとする
2. Model_Weightsが欠落または破損している場合、Chord_Estimatorは説明的なエラーメッセージを返すものとする
3. Chord_Estimatorは読み込まれたModel_WeightsでInference_Engineを初期化するものとする
4. モデルが読み込まれた時、Chord_Estimatorはモデルアーキテクチャが期待されるChordAI仕様と一致することを検証するものとする

### 要件2: テンプレートマッチングをChordAIに置き換え

**ユーザーストーリー:** ユーザーとして、テンプレートマッチングの代わりにChordAIモデルを使用したい。そうすることで、より正確なコード認識が得られる。

#### 受け入れ基準

1. Chord_Estimatorはすべてのコード認識タスクにChordAI_Modelを使用するものとする
2. Chord_EstimatorはAudio_PipelineからすべてのTemplate_Matcherロジックを削除するものとする
3. 音声特徴が提供された場合、Chord_EstimatorはそれらをInference_Engineに渡すものとする
4. Chord_Estimatorは以前のTemplate_Matcher出力と同じ形式でコード予測を返すものとする

### 要件3: マイナーコード認識の改善

**ユーザーストーリー:** ユーザーとして、正確なマイナーコード検出が欲しい。そうすることで、コード分析が実際の音楽と一致する。

#### 受け入れ基準

1. マイナーコードが音声に存在する場合、ChordAI_ModelはChord_Qualityをマイナーとして正しく識別するものとする
2. ChordAI_ModelはTemplate_Matcherよりも高い精度でメジャーコードとマイナーコードを区別するものとする
3. すべてのコードタイプ（メジャー、マイナー、ディミニッシュ、オーグメント）について、ChordAI_Modelは類似した音声入力に対して一貫した予測を生成するものとする

### 要件4: ベース音と転回形の検出

**ユーザーストーリー:** ユーザーとして、ベース音とコードの転回形を検出したい。そうすることで、完全なコード情報が得られる。

#### 受け入れ基準

1. コードの転回形が存在する場合、ChordAI_ModelはBass_Noteを識別するものとする
2. Chord_Estimatorはコード予測出力にBass_Note情報を含めるものとする
3. コードが基本形の場合、ChordAI_ModelはBass_Noteがコードのルートと一致することを示すものとする

### 要件5: 音声パイプライン互換性の維持

**ユーザーストーリー:** 開発者として、ChordAI統合が既存の音声パイプラインと連携することを望む。そうすることで、他のコンポーネントを変更せずに機能し続ける。

#### 受け入れ基準

1. Chord_EstimatorはTemplate_Matcherと同じChroma_Features入力形式を受け入れるものとする
2. Chord_EstimatorはTemplate_Matcherと同じ出力形式でコード予測を生成するものとする
3. Audio_Pipelineは上流または下流のコンポーネントへの変更を必要とせずに音声ファイルを処理するものとする
4. ChordAI_Modelが統合された場合、Audio_PipelineはTemplate_Matcherベースラインの20パーセント以内で同じタイミングとパフォーマンス特性を維持するものとする

### 要件6: モデル依存関係の処理

**ユーザーストーリー:** 開発者として、システムがChordAIモデルの依存関係を管理することを望む。そうすることで、手動での依存関係インストールなしにアプリケーションをデプロイできる。

#### 受け入れ基準

1. Chord_EstimatorはChordAI_Modelに必要なすべてのPythonパッケージを文書化するものとする
2. Chord_Estimatorは初期化時に必要な依存関係がインストールされていることを確認するものとする
3. 必要な依存関係が欠落している場合、Chord_Estimatorは欠落しているパッケージをリストした説明的なエラーメッセージを返すものとする
4. Chord_Estimatorは既存のAudio_Pipelineと互換性のある依存関係バージョンを使用するものとする

### 要件7: 既存機能の保持

**ユーザーストーリー:** ユーザーとして、ChordAI統合後もすべての既存機能が動作し続けることを望む。そうすることで、機能を失わない。

#### 受け入れ基準

1. Audio_Pipelineは同じ入出力インターフェースで音声ファイルを処理し続けるものとする
2. Chord_Estimatorはキャッシュシステムとの互換性を維持するものとする
3. Chord_Estimatorは歌詞アライメントシステムとの互換性を維持するものとする
4. Chord_Estimatorはコード可視化システムとの互換性を維持するものとする
5. ChordAI_Modelが予測を生成する場合、Audio_PipelineはTemplate_Matcherと同じ後処理ステップを適用するものとする

### 要件8: モデル出力品質の検証

**ユーザーストーリー:** 開発者として、ChordAIモデルがテンプレートマッチングよりも良い結果を生成することを検証したい。そうすることで、統合が精度を向上させることを確認できる。

#### 受け入れ基準

1. Chord_Estimatorは同じ音声入力に対して参照アプリケーション品質と一致するコード予測を生成するものとする
2. 既知のコード進行を持つすべてのテスト音声ファイルについて、ChordAI_ModelはTemplate_Matcherよりも高い精度を達成するものとする
3. ChordAI_ModelはTemplate_Matcherが失敗するテストケースでマイナーコードを正しく識別するものとする
4. ChordAI_ModelはTemplate_Matcherがベース音データを生成しないテストケースでBass_Note情報を正しく識別するものとする
